# Farming item-name cache verification

This is change evidence, not release notes. Fixtures use invented item labels.
Private coverage probes and their inputs stay outside the repository.

## Contract

- Coach stores `ForeverCoachDB.itemNames[id] = {n = name, q = quality}`;
  unknown quality is omitted. No new SavedVariables global or schema version.
- Login/world entry and auction-house close enqueue missing history IDs only.
  Cached and asynchronous completions share one 0.1-second timer; combat pauses
  work until `PLAYER_REGEN_ENABLED`. No eviction or new entries at 10,000.
- The implementation is a self-contained block in `Core.lua`, beside the
  existing item API reader. Adding a TOC file failed the updater's exact module
  allowlist. The unchanged TOC now passes `TestFarmNameCoachTOCUpdaterContract`.
- The addon remains 1.8.0/schema 1. Existing harness/version conventions do not
  require a feature-branch bump; publishing a new package remains a separate
  version/release decision. The legacy public-bundle test fixes its own 1.4.0
  archive fixture and is not a trigger for a Coach version bump.
- Name priority is AH Profit save, its bundled files (unchanged), Coach,
  installed GearQuest generated data, then `item <id>`. Quality comes only from
  the winning name source, never from a lower-priority name. AH Profit's current
  name/vendor tables carry no quality; GearQuest facts/audit rows can carry it.
- Hot and bank/sell rows are the only numeric item-label fallbacks. Auction
  statistics already have names, not item IDs; listing totals have no item rows.
  Their data does not provide quality. No name-to-ID guessing was added.
- GearQuest input is parsed as bounded Lua literals, never executed: 4 MiB/file,
  32 MiB total, 64 files, 250,000 parsed values/table, 50,000 retained items,
  at most 16 assignments/file; plain directories/files only. No dependencies.
- No hot ranking/filter changes. No Journey/guide content changes.

## Red then green

The initial Lua login test failed before implementation. Expanding it to async
loading/throttling failed before the queue implementation. Separate tests caught
synchronous successful-but-unreadable load loops and permanent `Item <id>`
placeholder caching before their fixes.

The initial Go name-source tests failed before name plumbing. The assignment
budget test failed with that guard removed, then passed with it restored. The
real shipped TOC/updater test failed with an added module, then passed after
moving the isolated module into Core without changing the updater contract.

Additional external controls exercised the actual committed tests, without
changing clone files:

- Disabled-cache control: `Ran 11 tests`, `FAILED (failures=7, errors=4)`.
- Nine Lua mutants all failed assertions (no errors): throttle bypass, combat
  bypass, cap overflow, known-name requery, donor mutation, quality omission,
  name-validation bypass, placeholder acceptance and synchronous retry loops.
- Eight Go overlay mutants failed the targeted tests: per-file/total bytes,
  file count, parser values, aggregate item count, Coach count, source priority
  and quality classes. Removing only the file-mode check did not fail because
  the independent opened-file identity and size checks still rejected symlinks;
  the unmodified symlink regression passed.
- Restored implementation: `test/item_names_test.py`: `Ran 11 tests`, `OK`.
