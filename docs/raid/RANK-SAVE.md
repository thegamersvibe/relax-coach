# Account rank readings (officer-lock stage 1)

`RelaxRaidDB.ranks` is additive to account schema version **1**. There is no
new SavedVariables name, TOC entry, dependency or prep-format change.

```lua
RelaxRaidDB.ranks = {
    ["Alia-Stone-PvP-EU"] = {
        result = "officer",
        guild = "Invented Guild",
        readAt = 1800000000,
    },
}
```

- Keys are the full character name from existing `Prep.identity()`, preserving
  case, surname and realm. Only the local character writes its own entry;
  this table is not sent over the raid channel.
- `result` is the existing `Log.readRank()` result: `officer`, `member`,
  `noguild` or `unreadable`. `pending` writes nothing, retaining the old entry
  and timestamp even after the logger's separate rank-wait timeout.
- `guild` is the first `GetGuildInfo("player")` return, exactly as read when it
  is a non-secret string of at most **96 bytes** with no control bytes
  (0–31 or 127). Empty strings and printable punctuation remain as read.
  Missing, secret, throwing, non-string, overlong or control-containing reads
  omit the field, never truncate it; a previous guild name is not carried forward.
- `readAt` is integer server time from `GetServerTime()`, using the existing
  prep timestamp validation (0–9999999999). An unreadable identity leaves the
  earlier entry unchanged because there is no safe own-character key.
  With a readable identity, a settled **member / noguild / unreadable always
  replaces the earlier row**, even if the clock is missing, secret, throwing
  or invalid: save the negative result with **no `readAt`**. Never carry forward
  the officer result or its old timestamp. A missing `readAt` does not admit
  the character in the app. An officer reading without a valid clock cannot
  refresh/create positive evidence and leaves the earlier row unchanged.
  The separate pending-preserves-old-reading rule still applies.
- Capture runs after Store initialization, at `PLAYER_ENTERING_WORLD`,
  `GUILD_ROSTER_UPDATE` (payload ignored) and own `PLAYER_GUILD_UPDATE`.
  It does not depend on logging being enabled or being in a raid.
- Existing `Store.writable()` gates apply: newer account, prep or character
  saves are untouched. Other root fields and prep data are not replaced by a
  capture. There is one latest row per local character, not a history of
  readings or guild-roster members.
- The table holds at most **50 rows**. At initialization (even with pending
  rank) and after a write, invalid rows are removed before their fields are
  used. A row needs a key accepted by `Prep.nameKey`, one of the four settled
  results, an optional bounded guild and an optional valid integer `readAt`;
  non-table rows, unknown fields and invalid present values are rejected.
  A non-table `ranks` value is ignored/removed. Valid rows and their spelling
  are retained, including clockless negative rows.
- Overflow drops rows without `readAt` first, then the oldest `readAt`.
  Equal times (including two missing times) drop the lexicographically smaller
  exact name first, independent of Lua table iteration order. Replacement of
  an existing character at capacity does not evict another character. A new
  clockless row can itself be dropped on overflow; it cannot leave an older
  officer row at the same key. Pending preserves valid old evidence, subject
  only to saved-row validation and this cap.

All client reads reuse guarded helpers (`Prep.read`, `Prep.identity`,
`Prep.number`) and `Log.readRank`; secret rank/name checks precede nil
comparisons. No value is declassified. Native secret equality cannot be fully
modelled by the Lua 5.1 harness, so the ordering has a source guard as well as
behavioral secret tests.

This is a **convenience lock, not security**: local saves are editable and may
be stale. Stage 1 only writes evidence. The app/page lock, selected-account
validation, input caps and server-side device-link check belong to their
separate lanes.

## Compatibility

`Store.Init` preserves unknown root fields and still writes root version 1.
The current app's `prepread.scanStore` selects `version` and `prep` without
rejecting other root keys. Apps 1.8.0 and 1.8.1 have the generic
`desktop/luasv.go` literal parser, not a raid-rank or prep-page reader.
`test/raid/rank/test_old_apps.py` executes those unmodified published parsers
against `save.lua` and `save-omitted-guild.lua`, generated by the real addon
with rank and prep data. The latter omits a 4,096/4,097-byte or control-containing
guild and carries clockless negative readings. It also runs the existing
real-bundle installer probe for **both** published apps. This proves
literal/save compatibility, not that those apps use ranks.

`test_rank.py` also feeds full real-writer output with 96-, 4,096- and
4,097-byte guild inputs to the unchanged current `prepread.Parse` through a
Go test overlay. Each must retain the existing preparation report without
warnings or skipped data; an overlong optional guild must not make prep unreadable.

Historical prep-only fixtures remain byte-identical: their mock client's rank
is left pending. The new full-save fixture is independently reproduced by
`test_rank.py`, so the additive fields are not removed to pass compatibility.
