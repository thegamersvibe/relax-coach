### Layout and accounting decision

`prep.version` is 2; account/character versions remain 1, wire version remains
1, and the TOC Version remains **0.2.0**. R2 is unreleased, so the nested schema
version identifies this layout without a separate addon release bump. This is
not an app-1.8.0 prohibition on higher addon versions. Existing 0.2.0 mock/test
pins remain consistent; `test_app_180_contract` and the real Go TOC contract
pass. The two SavedVariables declarations, dependency prohibition and addon
file inventory are unchanged.

Each night now contains:

- `day`: unchanged receiver UTC-noon bucket;
- `reports[key]`: a dense, oldest-first list of **canonical eleven-field wire
  body strings**, not expanded report tables;
- `windows[i] = {openedAt, reports = {[key] = {receivedAt, report = index}}}`.

The index resolves within that night's same-character body list. The later Go
reader follows it and parses the documented body grammar; `model.PrepReport`
is unchanged. `test/raid/_client/prep_store.py` exercises the lookup using the
real Wire decoder. Existing Store/Wire assertions now follow the index, while
retaining their identity, validation, timestamp and copy checks.

Store re-encodes the validated report via `Wire.encode` for both own and remote
puts and on reload. `#body` is the deterministic accounting unit; no caller
length or persisted byte counter is trusted. Bare names include the normalized
realm in this canonical measurement. The first retained body's `sentAt` stays
in its string, but comparison omits precisely field 8. All other validated
fields, including list order and reason, participate. Equal latest reports
reuse the index; A-B-A appends three entries. A new receipt still updates its
window's `receivedAt`.

The per-character/night limit is inclusive at 100000 body bytes. Overflow
removes that character's oldest bodies, removes its affected window entries,
and shifts only its remaining indices. Empty windows are pruned immediately;
window/player-cap eviction also removes an entirely unreferenced character's
body list. A referenced character's historical distinct bodies remain subject
to its own byte budget. There is no guild-sender gate and no new shared budget.

### Rule and unchanged layout

A night retains at most **4,000,000 canonical wire-body bytes** across all
characters. On overflow, drop the **oldest distinct body of the largest byte
holder**, with the **lowest whole-name key** breaking equal-byte ties; update
that holder's total and repeat until the night fits. All references to dropped
bodies disappear, higher indices shift down, empty windows disappear, and an
entirely unreferenced character's remaining history is removed too. Existing
per-character 100,000-byte trimming runs first. The 3-night, 80-window and
40-characters/window caps remain unchanged.

The same night rule runs on validated reload. `prep.version` stays **2**: body
strings and `{receivedAt, report=index}` rows are unchanged. A weak-keyed,
session-only accounting table avoids rescanning the entire night on every put;
it is rebuilt from validated bodies on load and never appears in the save.
Every append, oldest-body removal and orphan cleanup adjusts it. Only the
selected holder's references need scanning during night eviction. No supplied
body length or saved accounting value is trusted.

Thus the body bound is **3 * 4,000,000 = 12,000,000 bytes**, plus at most
**3 * 80 * 40 = 9,600 window references** and layout/serialization overhead.
A full 40-player night at exactly 100,000 bytes each fits with no eviction.
